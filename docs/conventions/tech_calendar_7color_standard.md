# 日历 7 色视觉规范与代课调度规约 (7-Color Calendar Standards)

本文档规定了 Dream 排班日历的 7 色视觉渲染标准、代课双视角表现及时间网格规范。

---

## 1. 营业时间窗与日历网格

- **营业时段**：每日 **06:00 - 00:00**（早夜均有排课需求）。
- **基础网格单元**：每个时间网格为 **30 分钟**，全天共 36 个基础日历网格。
- **排课占用标准**：
  - **1v1（一对一）**：标准授课 25 分钟，占用日历网格 **30 分钟**（含 5 分钟课间缓冲）。
  - **小班课（1vN）**：标准授课 50 分钟，连续占用日历网格 **1 小时**（2 个基础网格单元）。

---

## 2. 7 色日历状态渲染矩阵与代课双视角

日历系统对网格实施严格的 7 色状态渲染，特别对**代课场景实施双视角差异化染色**：

| 颜色标识 | 状态名称 | 视觉样式 (Tailwind) | 适用视角与核心业务说明 |
| :--- | :--- | :--- | :--- |
| 🟠 **橙色** | **固定位** | `bg-amber-500 text-white` | **全端通用**：已排定的四周一轮固定位正课（具备最高锁位优先级；若发生线下转让，保持橙色并加注【转】字角标与接收学生昵称）。 |
| 🟡 **黄色** | **临时课** | `bg-yellow-400 text-gray-900` | **全端通用**：家长提前 1-7 天自主预约的临时正课。 |
| 🔵 **蓝色** | **被代课** | `bg-blue-500 text-white` | **仅在【原被代课老师、班长、家长/学生】视图显示**：提示本节课由代课老师上，不计原老师课酬。 |
| 🟣 **紫色** | **代上课** | `bg-purple-600 text-white` | **仅在【代课老师】视图显示**：提示接手替别人代课，完课后计入代课老师课酬，可点开学生留言板看交接进度。 |
| ⚪ **灰色** | **教师不可约** | `bg-gray-200 text-gray-500 dark:bg-gray-800` | **全端通用**：教师未开放授课的日常休息时段。 |
| 🟢 **绿色** | **空闲可约** | `bg-emerald-500 text-white` | **全端通用**：教师常规开放授课且未被占用的时段。 |
| 🔴 **红色** | **已请假** | `bg-rose-500 text-white` | **全端通用**：教师主动标记请假或整班停课的时段。 |

## 3. 代课调度底层数据流

当班长在后台为某节 TS 协调代课老师时：
1. **资金持有人锁定**：TS 的 `holder_id` 保持最初收款班长不变。
2. **状态更新**：
   - `is_substitute = true`
   - `original_teacher_id = 原老师A_ID`
   - `current_teacher_id = 代课老师B_ID`
3. **课酬归属流转**：该 TS 完课后，课酬节数严格计入代课老师 B 的周课酬单中，绝不计入原老师 A。

---

## 4. 后端 DTO 预计算与接口规范 (colorCode 预下发)

为了避免前端在 Web 端和移动端重复编写复杂的代课双视角与角色逻辑判断，系统实施**后端预计算色值策略**：

- **接口下发规范**：
  日历查询接口（如 `GET /api/dream/v1/schedule/timeslots`）在返回 TS 列表时，Service 层根据当前登录身份（Token 中的 `account_id` 与角色）与 TS 关联关系，直接在 DTO 中注入预计算字段：
  ```json
  {
    "id": "ts_1234567890",
    "lessonDate": "2026-11-10",
    "timeSlot": "09:00-09:30",
    "status": "scheduled",
    "colorCode": "BLUE", // 枚举: ORANGE | YELLOW | BLUE | PURPLE | GRAY | GREEN | RED
    "colorLabel": "被代课",
    "isTransferred": false,
    "actualStudentNickname": "AliceZ12"
  }
  ```
- **全端哑组件化**：
  前端组件仅需根据 `colorCode` 映射 Tailwind 样式类，不持有复杂的代课视角推断逻辑，确保多端一致性。

---

## 5. 移动端手感与交互优化 (Mobile UX)

- **避免二维大表横向破形**：移动端（`tdesign-mobile-vue`）屏幕宽度有限，日历废弃传统 PC 端 7 列宽表格。
- **抽屉与卡片流交互**：
  - 采用顶部**“日期横向吸顶滑动条 (Horizontal Scroll)”** + 下方**“时段卡片流”**。
  - 预约与详情操作统一采用**“底部抽屉面板 (Bottom Sheet / `t-popup`)”**呈现，保障移动端单手操作的流畅度与沉浸感。
