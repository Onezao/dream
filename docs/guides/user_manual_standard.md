# Dream 用户手册编写规范（User Manual Standard）

> 本文件是 Dream 各类用户手册（家长端、教师端、班长端、管理员端）的编写标准。适用于 `docs/guides/` 下的 Markdown 手册，以及由手册衍生的 PPTX 版本。

---

## 1. 目的与适用范围

- 统一各类用户手册的结构、语气、截图与标注方式。
- 让非技术用户能按页面快速完成操作，不阅读代码、接口或内部规则。
- 适用于：家长端、教师端、班长端、管理员端及后续新增角色的操作手册。

---

## 2. 编写原则

1. **一页一功能**：每个页面只讲一个界面或一个完整任务。
2. **先操作，后规则**：先告诉用户“在哪里、点什么”，再补充必要规则。
3. **短句直述**：每页功能说明不超过 2 条；每条尽量一行。
4. **用户语言**：使用用户能听懂的业务词，不使用开发、数据库、接口、算法词汇。
5. **视觉优先**：每页必须有截图；关键区域用橙色虚线框标出。
6. **可执行**：用户读完一页，应能独立完成该页操作。
7. **不写内部实现**：不写状态码、错误码、字段名、缓存策略、后台任务和计算过程。
8. **不解释显而易见的结果**：用户能直接看到或自然理解的界面结果（如短消息在列表显示、长消息有详情按钮）不需说明；只写操作入口、关键限制与例外。
9. **不解释内部规则**：内部可见性、后台审核、系统拦截等用户不可见的规则不写入手册；只写用户需要执行的动作。

---

## 3. 文档结构

一份完整用户手册按以下顺序组织：

1. **封面信息**
   - 手册名称
   - 适用角色
   - 适用版本 / 日期
   - 维护人
2. **使用说明**
   - 本手册覆盖哪些页面
   - 截图与标注的使用方式
3. **目录**
   - 按角色或模块分组
   - 每个页面一条
4. **页面说明**
   - 每个页面使用统一模板（见第 4 节）
5. **常见规则 / FAQ**
   - 只保留用户日常会遇到的规则
   - 不写技术实现与内部状态
6. **术语表（可选）**
   - 只解释用户会看到的业务词
7. **版本记录**
   - 版本号、日期、修改人、修改内容

---

## 4. 标准页面模板

每个页面必须使用以下模板：

```markdown
## [页面名称]

*   [1 条功能说明：这个页面能做什么]
*   [1 条操作说明：用户主要怎么用]

**[截图：页面名称]**

### 橙色虚线框标注（Orange Dashed Borders）

- **[区域名称]**：框选[具体位置与范围]。
    - **Callout**：`[一句短说明，告诉用户这里能做什么]`

- **[区域名称 2]**：框选[具体位置与范围]。
    - **Callout**：`[一句短说明]`
```

### 模板要求

| 项目 | 要求 |
| :--- | :--- |
| 页面标题 | 使用用户熟悉的页面名称，如“学生课表”“我的购课单” |
| 功能说明 | 1–2 条，每条不超过 30 字 |
| 截图 | 每页 1 张，完整包含该页面主要内容 |
| 标注 | 每页 2–5 个橙色虚线框；不超过 5 个 |
| Callout | 每条不超过 20 字，使用动作或结果描述 |
| 页面长度 | 手机截图页面控制在 1 屏内讲完；长页面可拆成 2 页 |

---

## 5. 截图与标注规范

### 5.1 截图

- **手机页面**：统一使用 `390×812` 视口截图。
- **平板/复杂看板**：可使用 `768×860`，但同一手册内保持一致。
- **截图范围**：只截产品界面，不包含浏览器地址栏、开发者控制台、原型控制台。
- **数据脱敏**：真实姓名、邮箱、手机号、头像需替换为演示数据。
- **状态选择**：截图应展示该页面的典型可用状态，避免空白页或错误页。
- **文件命名**：`<角色>_<页面>_<状态>.png`，如 `parent_schedule_agenda.png`。

### 5.2 橙色虚线框

- 使用 **2px 橙色虚线矩形**，圆角与截图中的卡片圆角一致。
- 每个框对应一条 Callout，框内不要放文字。
- 框选范围只覆盖需要说明的区域，不要整页框选。
- 多个框按用户阅读顺序从上到下、从左到右排列。
- 框与框之间不要重叠；不要遮挡按钮文字。
- 建议颜色：`#F59E0B`（橙色），虚线间隔 4–6px。

### 5.3 Callout 写法

- 使用“动词 + 对象 + 结果”的短句：
  - `点击查询，按昵称查找待认领档案。`
  - `切换孩子，课表与课时一起更新。`
  - `确认后未读消息清零。`
- 不写实现细节：
  - 不写 `POST /api/...`、`status=PAID`、`holder_id`、`FIFO`、`L3 缓存`。
- 不使用威胁性或惩罚性词汇。

---

## 6. 语言与语气

- **默认语言**：中文简体。
- **英文版本**：仅当明确要求时提供；同一手册内不混用中英文标题。
- **语气**：客观、简短、直接；使用“点击、选择、查看、确认、切换”等动词。
- **人称**：统一使用“您”或省略主语，不混用“你/您”。
- **数字与单位**：积分、课时、天数、小时使用阿拉伯数字；如 `10 个`、`24 小时`、`4 周`。
- **按钮名称**：使用界面上的原文，如“同师挪位”“申请请假”“确认认领”。

### 6.1 推荐用词

| 场景 | 推荐表达 | 避免表达 |
| :--- | :--- | :--- |
| 临近开课不能改 | 授课准备期 / 开课前 3 小时内不可变更 | 熔断、锁死 |
| 退课/退费 | 课时退回、课时核销 | 冲退 |
| 小班课核算 | 班级运营核算、平台服务分成 | 自负盈亏、承包、抽佣 |
| 预约冲突 | 该时段已被预约，请重新选择 | 抢占 |
| 档案删除 | 注销档案、档案已注销 | 物理删除、清空 |
| 昵称占用 | 昵称已保留、不可再次使用 | 锁定死 |

---

## 7. 内容边界（不要写什么）

以下内容一律不写入用户手册：

- 数据库表名、字段名、Schema、SQL。
- API 路径、请求方法、状态码、错误码。
- 后端任务、跑批时间、队列、重试机制。
- 通知级别、邮件兜底时长、投递时间线。
- PWA 缓存级别、离线策略、IndexedDB / LocalStorage。
- 排序算法（如 FIFO）、计算公式的内部推导。
- 内部单据状态英文枚举（如 `PENDING_REFUND`、`SETTLED`）。
- 代码、日志、监控、部署、环境配置。
- 内部运营词、财务惩罚词、跨角色权限细节。
- 用户一眼可见的结果、显而易见的页面行为。
- 内部可见性、后台审核、系统拦截等用户不可见的规则。

**例外**：如果某个数字是家长/教师必须知道的业务规则（如“最多 10 个孩子”“提前 3 小时请假”），保留数字，但用用户语言表达。

---

## 8. 页面拆分建议

| 页面类型 | 拆分方式 |
| :--- | :--- |
| 列表页 | 1 页：筛选、列表、主要操作 |
| 详情页 | 1 页：身份信息、关键数据、主要操作 |
| 表单/弹窗 | 1 页：字段分组、校验提示、提交按钮 |
| 复杂看板 | 按角色或任务拆成 2–3 页，不把整屏压缩到一页 |
| 长流程 | 按步骤拆页，每页只讲一个步骤 |

---

## 9. 文件命名与目录

- 手册文件：`docs/guides/<角色>_<模块>_guide.md`
  - 示例：`parent_user_guide.md`、`teacher_schedule_guide.md`、`monitor_finance_guide.md`
- 截图目录：`docs/guides/assets/<手册名>/`
  - 示例：`docs/guides/assets/parent_user_guide/parent_home.png`
- 版本号写在文件开头：
  - `版本：v1.0`
  - `更新日期：YYYY-MM-DD`
  - `适用版本：Dream vX.Y`

---

## 10. 版本记录

每份手册末尾保留版本记录：

| 版本 | 日期 | 修改人 | 修改内容 |
| :--- | :--- | :--- | :--- |
| v1.0 | 2026-11-10 | [维护人] | 初版 |

规则：

- 页面新增、删除或操作流程变化时，必须升版本。
- 只改文案或截图时，可升小版本（如 v1.1）。
- 历史版本不覆盖，保留变更记录。

---

## 11. 审核清单

发布前逐项检查：

- [ ] 每个页面都有标题、1–2 条功能说明、截图、2–5 个橙色虚线框。
- [ ] 截图是当前版本界面，数据已脱敏。
- [ ] 框选位置准确，未遮挡按钮文字。
- [ ] Callout 简短、可执行，没有技术术语。
- [ ] 页面顺序符合用户实际操作顺序。
- [ ] 没有数据库、接口、状态码、缓存、队列、算法内容。
- [ ] 没有敏感词、惩罚性词汇或内部运营黑话。
- [ ] 同一名词全文一致（如统一用“宝贝”或“孩子”）。
- [ ] 数字、单位、时间窗口与最新业务规则一致。
- [ ] 文件命名、截图目录、版本记录完整。

---

## 12. PPTX 版本（可选）

仅当明确要求输出 PowerPoint 时：

1. 先按本规范完成 Markdown 手册。
2. 使用 `pptx` 技能生成演示文件。
3. 一页幻灯片对应一个手册页面。
4. 每页保留：页面标题、1–2 条功能说明、截图、橙色虚线框与 Callout。
5. 不在幻灯片中加入技术架构、接口或内部流程。

---

## 13. 模板示例

```markdown
## 学生课表

*   查看孩子本周的课程安排。
*   可切换孩子或切换周次查看。

**[截图：学生课表]**

### 橙色虚线框标注（Orange Dashed Borders）

- **孩子切换**：框选页面顶部的 Alice/Bob 标签。
    - **Callout**：`切换孩子，课表与课时同步更新。`

- **周次切换**：框选第 1–4 周与上一轮/下一轮。
    - **Callout**：`点击周次快速查看不同周安排。`

- **课程卡片**：框选课程时间、老师与教室。
    - **Callout**：`点击查看课程详情与可执行操作。`
```
