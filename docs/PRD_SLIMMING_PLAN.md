# Dream 系统精简方案 (PRD Slimming Plan)

> **核心哲学**：**「前端宽进宽出（把灵活性和信任还给人），后端账目分明（把精准、日志和对账留给系统）。」**  
> **核心目标**：做减法，专注 **「把排课做到极致流畅、把课酬算得清清楚楚」**，砍掉低频重耦合模块与过严的硬性业务拦截，降低研发与运营摩擦成本。

> **状态**：方案归档待逐步落地（2026-11-13）

## 一、 核心极简骨架 (Core Kernel)

减法做完后，全系统只保留 **4 个最纯粹的核心闭环**：

```text
┌─────────────────────────────────┐  ┌───────────────────────────────┐  ┌──────────────────────────────────┐  ┌──────────────────────────────┐
│            人与档案              │  │           购课录单             │  │            极致排课               │  │          精准课酬             │
│                                 │  │                               │  │                                  │  │                              │
│  外教 / 学生 / 班长 / 管理员     ├─►│         M2A 购课录单           ├─►│       M3A/M3D 日历与排课         ├─►│       M5 周结算对账           │
│                                 │  │                               │  │                                  │  │                              │
│  (极简档案 + 自由备注随时改)      │  │ (4周一轮，收款裂变 TS 资产)     │  │ • 4周固定位 / 临时课 / 4周小班    │  │ • 按完课 TS 自动算外教课酬     │
│                                 │  │                               │  │ • 全局班长自由约课                │  │ • 出勤/代课异常一目了然        │
│                                 │  │                               │  │ • 随心挪课 / 代课 / 换学生        │  │ • 班长周转账单                │
└─────────────────────────────────┘  └───────────────────────────────┘  └──────────────────────────────────┘  └──────────────────────────────┘
```

1. **人（Profile）**：外教、学生、班长（全域操作）、管理员。学生/老师带一个随手改的「备忘录 (Notes)」。
2. **单（Order）**：4 周一轮购课单，收到钱生成 TS 课次。
3. **课（Calendar & Schedule）**：周日历 + 日看板。快速排课、临时约课、一键换人、指派代课。没有任何时间熔断与配额卡点，教务想怎么排就怎么排。
4. **钱（Settlement & Salary）**：每周一凌晨按实际完课 TS 出账：
   - **老师课酬单**：列出上周上了几节、代了几节、哪些异常，金额清清楚楚；
   - **班长转账单**：上交课酬 + 固定工具费。

## 二、 6 大维度断舍离 + 基础放权

除 **「取消请假次数/时间硬熔断（改后置提示）、班长全域约课、砍掉独立留言板（改学生简易备忘，保留 M1E 课件模块）」** 之外，全系统执行以下 6 大维度减法：

### 减法一：彻底砍掉独立转让模块 (`M3C`) → 简化为「更换实际上课学员」
- **原复杂设计**：独立的转让单、自由 TS 转让集市、受让资格校验、4 周同轮限制、防二次转让锁、双向交割与多方通知。
- **现实真相**：少儿教务的转课，本质就是 A 妈妈在微信群把课给 B 妈妈，然后告诉教务一声。
- **极简改造**：直接废弃 `M3C`。在日历课格或课次明细上，班长只需点击 **【更换实际上课学员】**，下拉换成另一个孩子即可，无需校验是否同家庭；财务出资人依然记原购课单，课表上变成新学生。线下家长如何结算，系统不介入。

### 减法二：大幅精简退款系统 (`M2B`) → 降级为「课时清退/扣减 + 财务备注」
- **原复杂设计**：专门的系统退款单据、10% 阶梯违约金自动公式、平台工具费沉淀、原路退款审批流、周转账单冲抵核算。
- **现实真相**：少儿教务中途退费极少，且 100% 是班长/校长在微信或支付宝线下直接把钱转给家长。
- **极简改造**：不需要电商级退款审批流。在学员档案资产卡上提供 **【课时清退/扣减】** 按钮：输入清退节数（如退 4 节），系统扣减未排课时并填写备注（如“线下退费微信转账 ¥600”）。周转账单中班长应交金额按实际完课核算，退款无需线上反复流转。

### 减法三：取消学生请假配额限制 (`12.5%`) → 请假本质就是「退期待排」
- **原复杂设计**：`12.5%` 请假配额严格计算、向下取整、请假超额强行阻断、请假记账本。
- **现实真相**：孩子感冒发烧请假，教务不会生硬拦截“配额超了不让请”。
- **极简改造**：彻底移除请假配额概念。请假在系统里的本质只有一句话：**「把已排的 TS 释放变回待排期，日历格腾给别人」**。是否补课或允许请假由班长线下与家长沟通，系统不做前置拦截。

### 减法四：取消请假与调课的时间熔断 (`3h / 24h`) → 改为「开课前温和提示 + 出勤流水」
- **原复杂设计**：距开课 `< 3h` 强行锁死、禁止退改、管理员特批急病通道 B 录 10 字原因并强制写审计。
- **极简改造**：任何时候班长都能调课、挪位、换人。若在临开课前 3 小时内调整，系统仅弹出温和提示：**“距开课不足 3 小时，老师可能已进入备课状态，请确认已与外教沟通”**，点击确定直接放行。决策权交给教务，不搞系统死锁；相关记录在课酬单出勤流水中透出。

### 减法五：大幅简化通知网络 (`M4`) → 砍掉 30 分钟未读监控与多级路由
- **原复杂设计**：一二三级通知分级、30 分钟未读扫描补发邮件、多节排课防刷合并算法、任务队列状态机。
- **现实真相**：老师上课看日历，家长看微信。
- **极简改造**：只保留最关键的触发邮件（1v1 自动续费账单发家长、被代课/排课通知发外教），端内只保留一个极简消息列表（小红点），砍掉复杂的超时扫描定时器和通信分发队列。

### 减法六：砍掉庞杂的 `dream.activities` 履约动态流
- **原复杂设计**：专门建表记录 14 类履约事件、异步扇出、垂直时间轴。
- **极简改造**：历史履约直接查 `lessons`（已完课列表就是最好的履约记录）；在学员档案和教师档案里保留纯文本的 **【教学与沟通备忘录 (Notes)】**，班长和外教随时打字随时保存。

## 四、 核心功能点对比表（现行 PRD vs 精简后）

| 功能域 | 现行 PRD 规则 | 精简后方案 | 核心收益 |
|---|---|---|---|
| **请假次数与时间限制** | 12.5% 请假配额硬限制 + 课前 3h/24h 阶梯熔断矩阵，超限直接拦截操作 | **取消硬拦截**，操作时仅做「本月/本单已请假 N 次」软提示；**异常数据直接透出到 M5B 教师/班长课酬单** | 减少排课现场扯皮与管理员手动解锁，用课酬单透明数据约束 |
| **班长约课范围** | 班长仅能操作名下/绑定权限内的老师与班级排课 | **班长可全局约课**，直接选择任意老师空闲时段为学员排课 | 消除跨班长协调瓶颈，提升排课效率 |
| **学员备注 / 留言板 / 课件** | 独立 M1D 留言板（双权限）+ 独立 M1E 课件库（文件上传、在学进度绑定） | **砍掉 M1D 留言板**，合并为 M1A「学员备注」纯文本随时修改；**完整保留 M1E 课件库与在学进度管理** | 去掉留言板权限矩阵与冗余沟通表单，同时保留外教备课所需的课件体系 |
| **课程转让** | 独立 M3C 转让单、剩余课次拆单、转让审核与接收方确认流 | **取消转让单**，保持原购课单与资金归属不变，排课时允许直接「更换实际上课学员」 | 复用财课分离原则，零额外单据即可完成转课需求 |
| **退费核算** | 独立 M2B 退费单、10% 违约金公式、手续费计算与多级审批流 | **简化为「课时核销 + 退款备注」**：手动确认退费后直接扣减/清零剩余未排 TS，填写退款金额与备注留痕 | 避免复杂公式与现实退费协商不一致，人工线下核对后一键平账 |
| **消息通知与兜底** | 三级通知矩阵 + 站内信未读 30 分钟自动触发邮件兜底任务 (`dream-worker`) | **取消邮件兜底与复杂分级**，仅保留核心约课/改期/结单的轻量站内提示（或微信手动复制提醒） | 砍掉邮件队列状态机与模板维护 |
| **动态流 (`activities`)** | 14 种业务事件写入 `dream.activities`，首页展示时间线动态流 | **取消独立动态流表**，需要追溯时直接看课节（TS）变更记录与财务单据状态 | 降低全系统写入耦合度 |
| **应急调度与日历** | 仅周度 7 列日历看板，跨人临时调课/代课需来回切筛选 | **新增日维度应急调度网格**（当天及前后 7 天、当前时间线、按老师/学生竖条左右滑动） | 直接赋能核心强项「把排课做精」 |
| **课酬单与出勤透明度** | M5B 仅汇总正常结课与分账金额 | **M5B 课酬单挂载出勤统计与异常标记**（正常完课、请假次数、代课、异常未上） | 直接赋能核心强项「把课酬算好、算明白」 |
