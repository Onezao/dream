# Dream 用户手册编写规范 (User Guide Standards)

> **适用范围**：`docs/guides/` 目录下的全部用户使用手册（包括 `.md` 与单文件 `.html`）。  
> **自动触发原则**：凡新建或修改 `docs/guides/` 目录下的任何文件，**必须**先读取并严格遵循本规范与 `writing-documentation-with-diataxis`（`write-guide`）技能要求。

---

## 1. 内容组织架构（以读者需求为中心）

严格借鉴 Diátaxis 四类内容边界来组织章节，但**不在正文中向最终用户暴露方法论术语**（如不出现 `Diátaxis`、`Tutorial`、`How-to`、`Reference`、`Explanation` 等字样）：

1. **手册导读**：用一张简表按“你现在想做什么”引导读者直达对应章节。
2. **入门教程**：手把手带新用户走通一条最短闭环路径（单一主线、不堆砌异常分支）。
3. **日常实操指南**：按用户高频真实任务拆分，直接给步骤与条件判断（“遇到 X 时怎么处理”）。
4. **核心业务流转图解** *(面向班长/管理员等需统筹多方协作的角色)*：用通俗流程图展示业务主线，并在图下拆解协作分工。
5. **界面与规则速查**：纯客观对照表（导航入口、7 色日历含义、通知触发规则），不夹带操作步骤。
6. **核心规则解析**：解释关键制度“为什么这样设计”，帮助用户理解规则边界，不夹带操作步骤。

---

## 2. 边界隔离与去技术化铁律

### 2.1 严格按角色裁剪范围（严禁无关内容）
- 只写**目标角色直接操作或直接受影响**的功能、界面与规则。
- 其他角色专属的后台流程、内部财务报表、系统内部概念，**一律不放**。

### 2.2 严禁出现研发过程编号与工程词汇
最终用户手册面向老师、班长、家长等终端用户，**绝对禁止**出现以下内容：
- **研发与文档编号**：如 `M0`、`M1A`、`M3B`、`M5A`、`PRD`、`AC`、`US` 等。
- **状态机与枚举原文**：禁止直接贴出 `stateDiagram-v2`、`状态跃迁`、`PENDING_PAYMENT`、`DRAFT`、`COMPLETED`、`SUBBED_IN` 等底层状态名。
- **工程与前端实现词**：如 `ts_id`、`holder_id`、`SlotOverride`、`dream-worker`、`audit_logs`、`3-Tab` / `4-Tab`、`36px`、`7px`、`原子裂变`、`物理隔离`、`跑批`、“30 分钟未读扫描补发”等。
- **已下线功能概念**：如“课程类型”“擅长课程”“课程资质”及通知“一级/二级/三级”编号。

### 2.3 通俗流程图与协作说明规范
- 展示多方协作的业务流转时，统一使用**普通用户能看懂的 Mermaid `flowchart`**（中文大白话节点与箭头，严禁使用双冒号等导致语法解析失败的写法）。
- 流程图下方说明各方分工时，**禁止**使用“你要做什么”“需要了解什么”等生硬直白问句，统一使用自然专业的分组小标题：
  - **`[角色]处理要点`**（如 `班长处理要点`、`主理人处理要点`）
  - **`联动影响与协作提示`**（说明老师端、家长端看到的同步变化与配合事项）

## 3. 角色高频提醒检查清单

撰写对应角色手册时，务必核对是否包含以下关键实际使用提醒：
- **邮件通知与客户端提醒**（所有涉及接收系统邮件的角色）：明确说明**注册时使用的 Email 即为后续接收系统通知的邮箱**，并提醒保持手机上对应 **Email App 的通知提醒处于开启状态**。
- **ClassIn 课表同步**（涉及老师或排课联动）：明确提醒 Dream 课表与 ClassIn 日历相互独立，收到排课/挪位/代课变动通知后，需**及时根据 Dream 系统课表同步更新 ClassIn 的课表或日历**。
- **3 小时与 24 小时边界口径**：严格以当前业务规则为准（例如：老师突发请假无 3 小时入口锁死、班长不锁 3 小时仅温和确认、系统次日凌晨 `02:00` 自动结课）。

---

## 4. 单文件 HTML 离线手册规范（按需生成 `.html` 时遵守）

当用户需要网页版手册或要求生成 `.html` 版本时，**必须激活 `frontend-design` 技能**并遵守以下工程约束：
1. **单文件、零服务器、零构建**：仅输出单个 `docs/guides/<role>_manual.html`，双击浏览器即可本地打开；**禁止**拆分为多文件 MDX/站点目录，**禁止**依赖本地端口服务或外部部署。
2. **100% Tailwind CSS**：通过 CDN 引入 Tailwind CSS，**严禁手写 `<style>` 标签**。
3. **布局与交互**：
   - 顶部采用对应角色的专属主题横幅（如老师深青绿 `bg-teal-800`、班长深梅红、家长夜蓝）；
   - 提供免刷新的板块筛选按钮（全部内容 + 各核心章节），方便快速定位；
   - 如页面包含业务流程图，直接内置 Mermaid CDN 脚本完成浏览器端渲染。
4. **交付前自检**：
   - 使用 Node.js `vm.Script` 校验页面内嵌 JavaScript 语法无误；
   - 检查零 `<style>` 标签；
   - 扫描全文件确认无第 2.2 节禁用词汇与研发编号。
